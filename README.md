## Dev, QA & Production Collaboration Platform

**A multi-environment application delivery platform designed to make development, testing, and production deployments more consistent and repeatable.**

[![Docker](https://img.shields.io/badge/Containerized-Docker-2496ED?logo=docker&logoColor=white)](https://www.docker.com/)

[![Kubernetes](https://img.shields.io/badge/Orchestration-Kubernetes-326CE5?logo=kubernetes&logoColor=white)](https://kubernetes.io/)

### 🎯 Project goals

- Separate application configuration and deployment environments for **Dev, QA, and Production**.
- Package frontend and backend services into Docker images.
- Use a consistent image-publishing workflow with Amazon ECR.
- Route application traffic through Nginx.
- Keep PostgreSQL data in a dedicated database service.
- Automate infrastructure and delivery steps as the platform evolves.
- Improve release repeatability, troubleshooting, and deployment confidence.

### ☁️ Amazon ECR image publishing

Set your own AWS region, account ID, repository, and image tags. The values below reflect the ECR repository used during this project; verify that it still exists in your AWS account.

```bash
export AWS_REGION="eu-north-1"
export AWS_ACCOUNT_ID="258408902605"
export ECR="${AWS_ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com"
export REPO="platformf_or_dev_qa_prod"

# Authenticate Docker to ECR
aws ecr get-login-password --region "$AWS_REGION" \
  | docker login --username AWS --password-stdin "$ECR"

# Tag local images (adjust source image names if yours differ)
docker tag backend-backend:latest "$ECR/$REPO:backend-v1"
docker tag frontend-frontend:latest "$ECR/$REPO:frontend-v1"

# Push images
docker push "$ECR/$REPO:backend-v1"
docker push "$ECR/$REPO:frontend-v1"
```
